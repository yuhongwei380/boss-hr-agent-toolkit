# Resume Screener

## 核心架构

```
JD + 简历 → [特征提取] → [JD 类型判定] → [硬门槛过滤] → [加权评分] → [个性化建议] → [结构化呈现]
```

---

## 第 0 步：JD 类型判定

**技术岗判定条件（任一满足即判断为技术岗）：**
- 包含编程语言：`Python / Java / Go / C++ / Rust / JavaScript / TypeScript / SQL`
- 包含框架/平台：`Spring / Django / React / Vue / TensorFlow / PyTorch / Docker / Kubernetes`
- 包含技术领域：`后端 / 前端 / 算法 / 数据开发 / 测试开发 / 运维 / 全栈 / 数据挖掘 / 机器学习 / AI`
- 包含中间件/数据库：`MySQL / Redis / MongoDB / PostgreSQL / Kafka / Elasticsearch`
- 含明确技术栈描述（如"熟悉 Linux"、"掌握分布式系统"）

**管培/非技术岗判定条件（任一满足即判断为管培岗）：**
- JD 含：`管培生 / 商务 / 运营 / 市场 / 人力 / 销售 / 行政 / 客服 / 产品 / 设计 / 财务 / 法务 / 采购 / 物流 / 供应链`
- JD**不包含**任何技术岗关键词
- JD 偏重软性技能：沟通能力 / 团队协作 / 责任心 / 执行力 / 抗压能力

**判定优先级：** 技术关键词优先 → 无技术关键词按非技术 → 均无默认管培权重

> ⚠️ 每次输出必须明确写出「岗位类型判定结果及判定依据」

---

## 第 1 步：特征提取

从 JD 提取：岗位名称、职责、硬性要求（学历/毕业时间/专业/年限）、技术栈（仅技术岗）、软性要求、加分项

从简历提取：毕业时间、学校、学历、专业、GPA、所在地、实习经历（企业/时长/职责/成果）、项目经历、竞赛获奖、证书、品格信号

---

## 第 2 步：硬门槛过滤

**一票否决项（不通过直接筛除）：**
1. **毕业时间不匹配**（JD 明确要求某届，不匹配则否。JD 未明确的跳过此项）
2. **学历不达标**（JD 要求本科，大专直接否）
3. **专业零交集 + 技能栈为零**（JD 招后端，简历无关且无编程经验）
4. **非在读**（实习岗要求在校生，已毕业直接否）

> "稍微搭边可以先过"→标记为「待定」进入评分池

**硬门槛结果表：**

| 候选人 | 毕业时间 | 学历 | 专业交集 | 在读状态 | 结论 |
|--------|---------|------|---------|---------|------|
| 姓名 | ✅/❌/🔄无要求 | ✅/❌ | ✅完全对口/▲部分相关/❌无关 | ✅/❌ | ✅通过/🚫淘汰/▲待定 |

---

## 第 3 步：加权评分（双模式）

### 模式 A：技术岗权重（修订版）

| 维度 | 权重 | 评分方法 | 说明 |
|------|:----:|---------|------|
| 学历 | **25%** | **严格执行学校分档表** | ⚠️ 必须根据学校实际档次查表，禁止给所有人相同分数 |
| 工作经验 | **30%** | 相关经验年限 + 业务匹配度 | 年限 2 年=60%, 3 年=75%, 5 年+=90%；有相关项目经验 +15% |
| 专业技能 | **25%** | JD 技能覆盖率 | 目标技能匹配数 × 20 + 基础 30 分 |
| 项目经历 | **15%** | 项目复杂度 + 相关性 | 完整度、与企业需求匹配度、是否企业实战 |
| 专业 | **5%** | 匹配度 0-100% | 优先专业=100%，相关=80%，无关=30-60% |

### 模式 B：管培/非技术岗权重（修订版）

| 维度 | 权重 | 评分方法 | 说明 |
|------|:----:|---------|------|
| 学历 | **25%** | **严格执行学校分档表** | ️ 必须根据学校实际档次查表，禁止给所有人相同分数 |
| 实习/项目 | **30%** | 专家打分 0-100% | 完整度、复杂度、与企业需求匹配度 |
| 竞赛/荣誉 | **15%** | 含金量与密度 0-100% | 国家级竞赛/奖学金>省级>校级 |
| 技能 | **15%** | 证书与工具覆盖 0-100% | 办公软件、语言能力、专业证书等实用技能 |
| 品格 | **10%** | 信号累计 0-100% | 领导力、沟通力、抗压力、自驱力 |
| 专业 | **5%** | 匹配度 0-100% | 优先专业=100%，相关=80%，无关=30-60% |

### 评分公式

```
单维度加权分 = 原始百分比 (%) × 该维度权重 (%)
总分 = Σ(所有维度加权分)
示例：学历原始值 65%，权重 25% → 学历加权分 = 65% × 25% = 16.25 分
```

> ⚠️ 每个维度的原始百分比必须写明依据

## 第 4 步：学历分档（严格执行）

### ️ 重要：必须根据候选人实际学校查表评分

**学校分档表：**

| 档次 | 分数 | 示例学校 |
|------|:----:|---------|
| C9 | 100 | 清华、北大、复旦、交大、浙大、中科大、南大、哈工大、西交 |
| 985 | 92 | 其他 985 高校 |
| 211 | 85 | 其他 211 高校 |
| 双一流 | 77 | 双一流建设高校 |
| 一本公办 | 71 | 省属重点一本 |
| 二本公办 | 62 | 普通公办二本 |
| 民办本科 | 53 | 民办高校、独立学院 |

**硕士加分规则：**
- 在本科基础上 +8%（如 985 本→92%，985 硕→100% 上限 100%）
- 专升本：取最高学历查表，若路径体现自驱力（大专→公办二本及以上），品格 +5% 附加分

**评分时必须：**
1. 提取候选人学校名称
2. 判断学校所属档次
3. 查表得到分数
4. 在评分依据中写明「学校名称 - 档次 = 分数%」

**错误示例：** ❌ 所有人都是「普通本科 65 分」
**正确示例：** ✅ 安徽中医药大学 - 一本公办 = 71%

## 第 5 步：个性化行动建议（必须）

### ⚠️ 重要：禁止模板化建议，必须根据候选人具体经历个性化

**推荐面试（≥70 分）每人必须包含：**
1. **候选人背景**：基于实际学校、专业、工作经历、项目经历、技能标签总结
2. **🎯 沟通方向**：针对该候选人的具体情况给出面试重点

**示例（正确）：**
> **赵一坤 - 77.75 分**
> - 背景：车辆工程专业 + 3 年动力域/底盘域测试（ABS/EPB/ESC）+ CANOE/TSMaster/UDS 技能
> - 沟通方向：重点确认是否有车架结构设计经验（非测试），询问 CATIA/SolidWorks 三维设计能力，了解车架强度仿真和焊接工艺熟悉程度

**示例（错误 - 模板化）：**
> **赵一坤 - 77.75 分**
> - 沟通方向：重点了解车架结构设计经验，确认是否熟练使用 CATIA/SolidWorks 等三维设计软件，询问焊接工艺和钣金工艺熟悉程度。

**待沟通确认（60-69 分）每人必须包含：**
1. **✅ 优势**：为什么值得联系
2. **❓ 需确认问题**：具体的、针对该候选人的问题

**不推荐（<60 分）：**
- 一句话列出所有不推荐候选人及原因

## 可复现性保障

1. **步骤不可跳步**：严格按 特征提取→JD 类型判定→硬门槛过滤→加权评分→个性化建议→结构化呈现 顺序执行
2. **每维度注明依据**：原始%取值必须附带明确理由
3. **学历评分严格执行分档表**：必须根据学校实际档次查表，禁止给所有人相同分数
4. **行动建议必须个性化**：根据候选人具体经历给出建议，禁止模板化
5. **分数公式公开**：每项加权分写出 `原始% × 权重 = 结果` 的算式
6. **保留硬门槛结果**：淘汰原因保留到最终输出
7. **排名表含所有维度列**：方便追溯分数来源
8. **同一 JD+ 同一组简历→同一组分数**

## 注意事项

- **区分度原则**：分数覆盖 0-100 全区间
- **学历评分必须区分学校档次**：C9/985/211/双一流/一本/二本/民办，每档分数不同
- **项目经历和技术栈有重叠**：评项目时已体现的技术栈不重复扣技术栈分
- **品格推测注明依据**
- **JD 类型判定必须明确输出**
- **多岗位时每个岗位独立筛选**
- **行动建议禁止模板化**：每个人的沟通方向和需确认问题必须不同
